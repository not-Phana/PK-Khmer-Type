3. Why I Use AI

I use Artificial Intelligence not as a shortcut to bypass hard work, but as a dynamic intellectual amplifier, a tireless technical educator, and an always-available pair programmer.

Coming from a self-taught background in Cambodia, I did not have access to senior software architects or expensive computer science labs. When encountering obscure system behaviors—such as the way Windows injects artificial Control keydown events when AltGr is pressed, or how the Web Audio API coordinates BiquadFilterNode sweeps—there is rarely a human tutor available at 2:00 AM to explain the underlying mechanics.

AI bridges this mentorship divide. I use AI to:

  • Demystify Complex Architecture: Break down Monaco Editor text models, Abstract Syntax Tree (AST) parsing, Server-Sent Events (SSE) streaming protocols, and Electron IPC boundaries.
  • Accelerate the Feedback Loop: Receive rapid diagnostic feedback when an algorithm misbehaves, tracing edge cases and discovering where assumptions broke down.
  • Explore Alternative Implementations: Compare approaches (e.g., HTML5 Canvas direct path rendering vs. DOM-based sprite translation) to understand memory tradeoffs and render performance.
  • Draft and Refine Boilerplate: Generate baseline structural boilerplate so I can dedicate my cognitive energy to core logic, edge-case handling, and user experience.

4. My Philosophy: AI Should Make Me More Capable, Not Dependent

AI must make me more capable as a thinker and engineer; it must never render me dependent or helpless.

I reject the culture of "vibe coding"—blindly prompting an AI, copying uninspected code, pasting it into a project, and hoping for the best. When something breaks, a vibe coder cannot explain why, cannot trace the call stack, and cannot fix the bug without begging the model for another patch.

For me, every interaction with an AI model is an educational contract:

  • If an AI suggests a regular expression for Khmer Unicode syllable clustering, I study the Unicode code blocks (\u1780-\u17D3) and verify why each character class exists.
  • If an AI helps structure an Electron preload script, I examine the contextBridge, study why nodeIntegration: false and contextIsolation: true prevent remote code execution, and verify the attack vectors myself.
  • If an AI generates a draft module, I refactor it, strip unnecessary code, align it with my strict naming conventions, and verify its runtime behavior in real browsers.

My foundational standard is simple: If every AI service on Earth shut down tomorrow, the knowledge I acquired while building must remain inside my head. AI is the bicycle for my mind; I am the one steering, pedaling, and navigating the terrain.

8. PK Khmer Type and Its Purpose

PK Khmer Type (v2.4 Pro Studio Edition) is my flagship public educational project. In Cambodia, typing Khmer is exceptionally challenging because the abugida script (33 consonants, 23 dependent vowels, 12 independent vowels, diacritics, and subscript Coeng signs) spans across four modifier layers (Base, Shift, Ctrl, AltGr).

I engineered a standalone, zero-dependency browser application designed to operate seamlessly both online and 100% offline from the local filesystem (file:/// protocol). It features:

  • Instant switching between Khmer Standard, Khmer NiDA, and English QWERTY.
  • A 40-level progressive curriculum with 218 lessons and 664 exercises featuring strict progressive character unlocking.
  • Dual-hand 3D kinematic finger guides (44% default opacity) dynamically pointing to target keys and modifier holds.
  • Procedural Web Audio switch synthesizer (Topre, Holy Panda, Cherry MX Blue, Linear) with zero external audio assets.
  • Live Mastery Dashboard (dashboard.html) with per-key latency/accuracy heatmaps and JSON profile backup/restore.
  • Zero-Lag Performance Mode to disable all animations for pure mechanical input speed.
  • Full bilingual UI (English / Khmer) toggled with a single shortcut (Alt + L).

9. PK Studio Code

An in-development developer environment exploring how code editors function internally. Built around the Microsoft Monaco Editor, it integrates multi-tab model states, bracket colorization, code minimap, an interactive terminal REPL, a real-time AST problem diagnostic panel, an extensible lifecycle plugin bus (PKPluginSystem), five custom dark themes, and a local Node.js Server-Sent Events live server.

23. First-Person Autobiography: An Honest Introduction

Hello. My name is Phley Phana. Most people online know me as Phana Kurosaki, and my friends and fellow builders call me KON.

I was born and live in Cambodia, a country with an ancient cultural heritage and a young, rapidly emerging digital future. I didn't begin with private tutors or a high-end gaming PC. I began with curiosity, an internet connection, an integrated-graphics computer, and a desire to see my ideas exist in the real world.

When I first opened a code editor in early 2026, I started like everyone else: making simple web pages with HTML and CSS, testing colors, and figuring out why a layout broke when the browser resized. My first public milestone on GitHub was Phana Coffee Shop, deployed to Vercel. It proved to me that if I put in the hours, code could become something people could actually visit and use.

From that moment on, I wanted to understand how deeper software worked. I experimented with Electron to build native Windows desktop tools: an offline audio player with a real 10-band equalizer (PK Music) and a desktop alarm utility (Arachne Clock). I explored game loops by writing a 60 FPS HTML5 Canvas action game (NEON PROTOCOL // OVERDRIVE) and building cooperative wave defense games in Luau on Roblox (Neon Core Defense).

Then I looked at the software environment around me in Cambodia. Typing in our native Khmer language has always been a steep hurdle across four keyboard layers. I built PK Khmer Type—a complete, zero-dependency typing studio featuring 40 levels, 218 lessons, dual-hand 3D kinematic finger guides, procedural audio switch synthesis, and a live mastery telemetry dashboard that works 100% offline.

To support my projects, I established the PK brand. Across all my work, I follow a strict Zero-Emoji Policy, crafting crisp 24x24 vector icons, which gave birth to PK Icons Studio. I began exploring IDE internals and AI companions through PK Studio Code and KON.

Throughout this journey, I have used Artificial Intelligence extensively. Tools like Google Antigravity, Claude, ChatGPT, and Codex have been my digital mentors, sounding boards, and co-authors. But I hold one rule above all others: AI is here to make me a stronger engineer, not a helpless passenger. I never accept code I don't understand, and I continuously study the mechanics behind the screen.

I am an independent builder at the beginning of a long journey. I have built real things, I have made countless mistakes, and I have learned from every single one of them. My goal is simple: to keep building software that is fast, useful, honest, and empowering.

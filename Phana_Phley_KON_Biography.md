## 4. My Philosophy: AI Should Make Me More Capable, Not Dependent

I hold an uncompromising personal philosophy regarding artificial intelligence:

> **AI must make me more capable as a thinker and engineer; it must never render me dependent or helpless.**

In contemporary software discussions, there is a dangerous trend known as "vibe coding"—the practice of casually typing prompts into a chatbot, copying whatever code is emitted without inspection, pasting it into a codebase, and hoping for the best. When something breaks, a vibe coder cannot explain why it broke, cannot trace the call stack, and cannot fix the bug without blindly begging the model for another patch.

I reject this mindset entirely. For me, every interaction with an AI model is a learning contract:
- If an AI suggests a regular expression for Khmer Unicode syllable clustering, I study the Unicode code blocks (`\u1780-\u17D3`), understand the Coeng subscript mechanics, and verify why each character class exists.
- If an AI helps structure an Electron preload script, I examine the `contextBridge`, study why `nodeIntegration: false` and `contextIsolation: true` prevent remote code execution, and verify the attack vectors myself.
- If an AI generates a draft module, I refactor it, strip unnecessary code, align it with my strict naming conventions, and verify its runtime behavior in real browsers.

My foundational standard is simple: **If every AI service on Earth shut down tomorrow, the knowledge I acquired while building must remain inside my head.** My architectural intuition, understanding of data structures, ability to read documentation, and capability to debug live systems must grow stronger with every commit, not weaker. AI is the bicycle for my mind; I am the one steering, pedaling, and navigating the terrain.

## 8. PK Khmer Type and Its Purpose

*PK Khmer Type* (currently in version 2.4 Pro Studio Edition) is my flagship public educational project. 

### The Problem It Solves
The Khmer script is an abugida writing system consisting of 33 consonants, 23 vowels (dependent vowels), 12 independent vowels, diacritics, and numerous subscript consonants (known as *Coeng*). Typing in Khmer on a standard physical keyboard is notoriously difficult:
- Keys have up to four distinct modifier states: **Normal (Base)**, **Shift**, **Ctrl**, and **AltGr (Right Alt)**.
- To type a subscript consonant, a user must first press the subscript generator key (key `J` on standard layouts, corresponding to Unicode `U+17D2` Khmer Sign Coeng) followed by the base consonant.
- Cambodia has two competing standard layouts: the legacy **Khmer NiDA** layout (widely used across government and administrative bodies) and the modern **Khmer Standard (Unicode)** layout, alongside standard English QWERTY.
- Most available typing tutors are outdated, filled with third-party advertisements, lacking structured curriculums, or completely incapable of running offline.

### What I Built
I engineered *PK Khmer Type* as a zero-dependency, high-performance browser application designed to run seamlessly both online via static hosting and 100% offline from a local hard drive (`file:///` protocol) without requiring Node.js or an active internet connection.

Key capabilities include:
- **Comprehensive Layout Support:** Instant keyboard switching between **Khmer Standard**, **Khmer NiDA**, and **English (US) QWERTY**.
- **Structured 40-Level Curriculum:** 218 sequential lessons and over 664 exercises engineered with strict progressive character unlocking—ensuring learners never encounter unintroduced glyphs.
- **Dual-Hand 3D Kinematic Hand Guides:** Anatomically accurate translucent left and right hand overlays tuned to 44% default opacity, dynamically highlighting target keys and modifier combinations.
- **Procedural Web Audio Synthesizer:** Real-time audio engine synthesizing mechanical switch feedback (Topre Thock, Holy Panda Tactile, Cherry MX Blue, Silent Linear) with zero external audio assets.
- **Live Mastery Dashboard (`dashboard.html`):** Real-time analytics reading local telemetry to generate per-key accuracy and latency heatmaps, WPM progression curves, and one-click JSON profile backup and restore.
- **Zero-Lag Performance Mode:** A dedicated high-performance toggle that turns off all transitions, background particles, and blur filters, ensuring zero input latency even on low-end hardware.
- **Bilingual Interface:** Instant switching between English and Khmer across all menus, tooltips, and lessons (`Alt + L`).

## 10. KON, My AI Assistant Concept

Named after my personal online nickname, **KON** is an experimental AI developer companion and code workbench that I designed and run locally.

### The Problem with Generic AI Chat Windows
Most commercial AI chat interfaces are detached from the developer's working context. You are forced to copy files back and forth, paste snippets into small text boxes, and receive generic, conversational responses that do not respect the architectural constraints of the project.

### The KON Architecture
KON was built as a focused, local AI developer workbench:

- **Server-Sent Events (SSE) Streaming:** Implemented progressive token streaming, rendering code blocks, Markdown explanations, and structural suggestions in real time as tokens arrive.
- **Context-Aware Diagnostic Prompts:** Pre-configured with structured engineering modes:
  - *Explain Code:* Walks through complex functions step-by-step, explaining memory flow and API interactions.
  - *Debug and Fix:* Pinpoints syntax errors, logic flaws, race conditions, or unhandled null states.
  - *Refactor Architecture:* Suggests ways to decouple bloated components, reduce cyclomatic complexity, and improve readability.
  - *Generate Unit Tests:* Constructs targeted test suites covering edge cases and boundary conditions.
- **Multi-Provider Routing Experiments:** Experimented with routing requests across Google Gemini models and OpenRouter endpoints to balance token cost, speed, and reasoning depth.

KON is not a commercial SaaS; it is my private engineering companion, crafted to help me think more deeply about the software I build.

## 13. My Relationship with AI Coding Agents, Especially Google Antigravity

I make a sharp distinction between two kinds of AI tools:
1. **Conversational Chatbots:** Web-based chat interfaces (like ChatGPT or Gemini in the browser) that provide helpful text summaries and ideation, but cannot touch your filesystem or run your code.
2. **Autonomous Coding Agents:** Tools like **Google Antigravity** (designed by Google DeepMind) that possess real terminal execution capabilities, local filesystem access, and browser inspection tools.

### Working with Google Antigravity
My experience working with Google Antigravity represents a fundamental shift in how software can be authored:
- **Terminal and System Execution:** Antigravity does not just write code into a markdown box; it executes PowerShell and Bash commands, inspects directory trees, launches background processes, and installs dependencies.
- **Visual and Headless Verification:** Using Chrome DevTools Protocol (CDP) and headless browser automation, Antigravity can navigate to running web applications, inspect live viewports, capture screenshots, and verify whether visual elements, keycaps, and canvas loops render correctly.
- **Multi-File Refactoring:** Antigravity can trace references across entire repositories, performing precise, coordinated edits across multiple source files while respecting architectural conventions.
- **Collaborative Co-Authoring:** On repositories like *PK Khmer Type*, autonomous agents participate as verified co-contributors—analyzing edge cases, running automated tests, and helping refine complex algorithms alongside my direct human architectural leadership.

This agentic partnership is the future of software development: a human architect directing vision, philosophy, and taste, paired with autonomous AI agents executing, testing, and verifying implementations in real time.

## 14. My Approach to Software Design and UI/UX

My design philosophy is governed by three classical Greek principles that I have embedded directly into the PK manifesto:

1. **Poiesis (Build):** The discipline of bringing ideas into tangible reality. Software should not remain a vague daydream; it must be built, tested, and shipped.
2. **Episteme (Understand):** Deep comprehension of craft. Never rely on an abstraction or library that you do not take the time to understand.
3. **Melete (Improve):** Disciplined, iterative refinement. Software is never "finished"; it is continuously polished, refactored, and tuned.

### Concrete UI/UX Guidelines
- **Restraint and Minimalism (*Meden Agan* — Nothing in Excess):** If a visual element does not serve a communicative or structural purpose, remove it. I avoid cluttered toolbars, unnecessary dropdowns, and decorative filler.
- **The Zero-Emoji Rule:** Emojis are strictly banned across my user interfaces, status badges, and documentation. I rely exclusively on crisp, monoline SVG vector icons.
- **Dark-Mode Dominance:** My interfaces prioritize high-contrast, eye-friendly dark color schemes—obsidian bases, deep charcoal surfaces, bronze/gold accent borders, and subtle cyan status indicators.
- **Zero-Lag and Motion Control:** Animations must never block user interaction. Heavy visual effects (like blur backdrops, particle systems, or smooth camera zooms) must always include an immediate toggle to disable them for users who value raw performance.
- **Bilingual Ergonomics:** Software built for Cambodia must treat Khmer and English as first-class citizens, ensuring typography is readable, properly kerned, and visually balanced in both scripts.

Rendering and typing the Khmer script in modern browsers presents unique challenges:
- Handling the physical Windows `AltGr` key, which fires a simultaneous artificial `Control` keydown event, requiring custom event-layer deduplication to prevent spurious layer switching.
- Navigating Zero-Width Spaces (`\u200B`), diacritic stacking order, and subscript Coeng combinations without breaking cursor position or text selection.

### 2. High-Performance Browser Graphics and Audio
Building *NEON PROTOCOL // OVERDRIVE* pushed the limits of vanilla browser APIs:
- Managing 60 FPS animation loops on HTML5 Canvas while handling particle explosions, collision mathematics, and bullet hell projectile swarms without triggering garbage collection pauses.
- Managing Web Audio API oscillator lifecycles, gain nodes, and user-gesture activation constraints across different browser engines.

### 3. Solitary Problem-Solving
As a solo developer, there is no team lead or senior engineer to hand me architectural blueprints. When an obscure bug emerges—whether a race condition in Electron IPC or an AST traversal error in Monaco—I must research the issue, read specification documents, analyze source code, and resolve it myself.

### 4. Overcoming AI Hallucinations and Incomplete Advice
AI models frequently invent plausible-sounding API methods, suggest deprecated packages, or fail to consider edge cases in niche environments like Khmer text layout. Learning to critically audit, test, and correct AI output is a constant, demanding requirement.
